# link-cache demo: benchmark report

Generated by `scripts/link-cache-demo-bench.sh` against
`examples/link-cache-demo/`.

## Project under test

Five-package diamond:

```
demo-core              (no internal deps)
   ↑       ↑
demo-codec   demo-graph
       ↑    ↑
       demo-engine
            ↑
         demo-app      (executable)
```

Most scenarios edit `demo-core/src/Demo/Core/Util.hs` (the deepest
module in the cone, so every link in the cascade is potentially
affected). One scenario (`edit-leaf-of-mid-lib`) edits
`demo-codec/src/Demo/Codec/Frame.hs` to probe what happens when
the edit lands halfway up the cone instead.

## Reproduce

```sh
scripts/link-cache-demo-bench.sh --cabal=/nix/store/vvlfv3m1bryfpsq1nn8lspnlyyy9csf0-cabal-install-3.17.0.0/bin/cabal --runs=3 --verify
```

## What this measures

A **novel-edit** rebuild. The link-cache is pre-populated with
the *baseline* link outputs and snapshotted. Each timed
cache-on iteration starts from that baseline-only cache, then
the scenario edit is applied and the build is timed. Links
whose inputs are byte-stable across the edit can still HIT
from the baseline snapshot; links whose inputs changed bytes
MISS and write the perturbed-state output to the cache. The
cache is reset to the baseline snapshot **before every**
iteration so the perturbed-state blobs written by iteration N
do not poison iteration N+1.

## How each scenario should behave (a priori)

| scenario | rationale |
|---|---|
| body-stable | wraps `every`'s body in a no-op `let`; at `-O1` GHC dead-code-eliminates the let. `Util.o` should be byte-equal to baseline → full cascade HIT (9/9). |
| add-unexported | appends a new private `_bench…` binding; underscore-prefixed unused bindings are dropped at `-O1` → 9/9. |
| add-exported | extends the export list. `Util.hi` grows; GHC may force downstream importers to recompile even when they don't use the new symbol. Expected: HITs only on packages that don't import `Util`. |
| modify-type | tightens `describe`'s constraint. Downstream importers of `describe` must recompile → cascade MISS. |
| refactor-internal | private `firstOf`→`headOf` rename. `Util.o` differs but `Util.hi` doesn't, so downstream `.o` files stay byte-stable. Expected: 6 HITs (middle libs) + 3 misses (demo-core×2 + exe — exe key includes demo-core.a bytes). |
| whitespace-only | append a blank line to `Util.hs`. Lexer should drop it → `Util.o` byte-equal → 9/9. |
| comment-only | append a `--` comment line. Same expectation as whitespace-only → 9/9. |
| reorder-exports | swap two adjacent exports without adding/removing any. GHC canonicalises the export order for the ABI hash, so `Util.hi` should be byte-equal → 9/9. |
| edit-leaf-of-mid-lib | append a private binding to `Demo.Codec.Frame`. Nothing imports `Frame` in this project, so `demo-core` + `demo-graph` should fully HIT; `demo-codec`, `demo-engine`, and the exe MISS. |

## Soundness

Each scenario was re-run once with `CABAL_LINK_CACHE_VERIFY=1`
and `CABAL_LINK_CACHE_VERIFY_FAIL=1`. In this mode the linker
is re-invoked on every cache HIT and the cached blob is
byte-compared against the freshly-produced output; any
divergence is escalated to a hard build error.

## Interpretation

The **`HIT/build`** column and the per-target outcomes table
together tell the story. On this project, novel-edit cache
wins stratify by the edit's effect on the touched module's
`.hi`:

- Edits GHC reduces to a byte-equal `.o` at `-O1` (body-stable,
  add-unexported, whitespace-only, comment-only) HIT the full
  cascade.
- Edits whose `.o` differs but whose `.hi` is stable
  (refactor-internal) keep middle libraries on the HIT side;
  the touched library and the exe (which links against the
  touched library's bytes via `linkDepArchives`) MISS.
- Edits that change the `.hi` (add-exported, modify-type)
  force GHC to recompile downstream importers; their `.o` files
  come out fresh, so the link cone above the change misses.
  Cache wins are confined to packages that don't import the
  touched module at all.
- `reorder-exports` is a positive control: GHC canonicalises
  export ordering for the ABI hash, so reordering should be
  invisible to downstream.
- `edit-leaf-of-mid-lib` probes the same partitioning logic
  from a different starting point: an edit to `demo-codec`
  leaves `demo-core` + `demo-graph` HITting, and only the
  ancestors of `demo-codec` in the cone MISS.
